Architecture Overview

The ISS Opportunity Manager is a self-contained HTML file that runs entirely in the browser. SharePoint acts as the central database, and Power Automate flows act as the API layer between the browser and SharePoint.

Create SharePoint Lists

Go to your SharePoint site → Site Contents → New → List. Create the following four lists with the exact column names below.

💡
All column names are case-sensitive in the Power Automate expressions. Use the exact names as shown. The Title column is renamed in some lists — rename it by clicking the column header.

4

Create Power Automate Flows

Go to make.powerautomate.com → Create → Instant cloud flow → trigger: "When an HTTP request is received".

⚠️
After saving each flow, copy the HTTP POST URL from the trigger step — you'll need this to configure the app. The URL includes a long SAS token and is unique per flow.
🔒
All Power Automate HTTP-triggered flows require the HTTP POST URL to work — treat it like a password. Anyone with the URL can call the flow.
Flow 1 — Get Opportunities

Called on app load to fetch all opportunity records from SharePoint.

  1. Trigger: "When an HTTP request is received" — Method: POST
  2. Action: "Get items" → SharePoint site → List: ISS_Opportunities → Top Count: 5000
  3. Action: "Select" (Data Operations) → From: value from step 2 → Map each field:
    Set the Map to include all columns: id, opportunityId, businessUnit, etc. (see JSON schema below)
  4. Action: "Response" — Status: 200 — Body: see JSON below — Headers: see CORS headers below

Response body:

{
  "items": @{body('Select')}
}

Select action mapping (map SharePoint columns → app field names):

{
  "id":                    "@{item()?['AppId']}",
  "opportunityId":         "@{item()?['Title']}",
  "businessUnit":          "@{item()?['BusinessUnit']}",
  "status":                "@{item()?['Status']}",
  "stage":                 "@{item()?['Stage']}",
  "customerName":          "@{item()?['CustomerName']}",
  "customerNumber":        "@{item()?['CustomerNumber']}",
  "offering":              "@{item()?['Offering']}",
  "industry":              "@{item()?['Industry']}",
  "serviceCategory":       "@{item()?['ServiceCategory']}",
  "estValue":              "@{item()?['EstValue']}",
  "closePercent":          "@{item()?['ClosePercent']}",
  "projectedCloseDate":    "@{item()?['ProjectedCloseDate']}",
  "projectedDeliveryDate": "@{item()?['ProjectedDeliveryDate']}",
  "createdBy":             "@{item()?['CreatedBy2']}",
  "createdDate":           "@{item()?['CreatedDate']}",
  "reasonWon":             "@{item()?['ReasonWon']}",
  "reasonLost":            "@{item()?['ReasonLost']}"
}
Flow 2 — Save Opportunity (Create & Update)

Handles both creating new and updating existing opportunities. The app always sends the full opportunity object.

  1. Trigger: "When an HTTP request is received" — Method: POST — Request body JSON schema: 
    {
  "type": "object",
  "properties": {
    "id": { "type": "string" },
    "opportunityId": { "type": "string" },
    "businessUnit": { "type": "string" },
    "status": { "type": "string" },
    "stage": { "type": "string" },
    "customerName": { "type": "string" },
    "customerNumber": { "type": "string" },
    "offering": { "type": "string" },
    "industry": { "type": "string" },
    "serviceCategory": { "type": "string" },
    "estValue": { "type": "number" },
    "closePercent": { "type": "number" },
    "projectedCloseDate": { "type": "string" },
    "projectedDeliveryDate": { "type": "string" },
    "createdBy": { "type": "string" },
    "createdDate": { "type": "string" },
    "reasonWon": { "type": "string" },
    "reasonLost": { "type": "string" }
  }
}
  2. Action: "Get items" → ISS_Opportunities → Filter Query: AppId eq '@{triggerBody()?['id']}'
  3. Action: "Condition" — check if length(body('Get_items')?['value']) is greater than 0
    • If yes (update): "Update item" → ISS_Opportunities → ID: first(body('Get_items')?['value'])?['ID'] → Set all field values from trigger body
    • If no (create): "Create item" → ISS_Opportunities → Set all field values from trigger body, including AppId: @{triggerBody()?['id']}
  4. Action: "Response" — Status: 200 — Body: {"success": true} — add CORS headers
Flow 3 — Delete Opportunity

Deletes a record from SharePoint by its app UUID.

  1. Trigger: "When an HTTP request is received" — Method: POST — Body: {"id": "..."}
  2. Action: "Get items" → ISS_Opportunities → Filter Query: AppId eq '@{triggerBody()?['id']}'
  3. Action: "Apply to each" → input: body('Get_items')?['value']
    • Inside loop: "Delete item" → ISS_Opportunities → ID: items('Apply_to_each')?['ID']
  4. Action: "Response" — Status: 200 — Body: {"success": true}
Flow 4 — Get Config (Dropdowns + Customers)

Returns all dropdown options and the customer list to populate the app's form fields.

  1. Trigger: "When an HTTP request is received" — Method: POST
  2. Action: "Get items" → ISS_Config → all items
  3. Action: "Get items" → ISS_Customers → all items
  4. Action: "Select" (for customers) → From: ISS_Customers value → Map: {"name": "@{item()?['Title']}", "number": "@{item()?['CustomerNumber']}"}
  5. Action: "Response" — Status: 200 — Body: 
    {
  "dropdowns": {
    "offering":       @{json(first(filter(body('Get_Config_items')?['value'], item()?['Title'] eq 'offering'))?['ConfigValues'])},
    "industry":       @{json(first(filter(body('Get_Config_items')?['value'], item()?['Title'] eq 'industry'))?['ConfigValues'])},
    "stage":          @{json(first(filter(body('Get_Config_items')?['value'], item()?['Title'] eq 'stage'))?['ConfigValues'])},
    "serviceCategory":@{json(first(filter(body('Get_Config_items')?['value'], item()?['Title'] eq 'serviceCategory'))?['ConfigValues'])},
    "status":         @{json(first(filter(body('Get_Config_items')?['value'], item()?['Title'] eq 'status'))?['ConfigValues'])},
    "reasonWon":      @{json(first(filter(body('Get_Config_items')?['value'], item()?['Title'] eq 'reasonWon'))?['ConfigValues'])},
    "reasonLost":     @{json(first(filter(body('Get_Config_items')?['value'], item()?['Title'] eq 'reasonLost'))?['ConfigValues'])}
  },
  "customers": @{body('Select_Customers')}
}
💡
The expression above uses filter() to find the config row by Title. If any dropdown key is missing from ISS_Config, that key will be null — the app will fall back to its built-in values for that dropdown.
Flow 5 — Validate User (Login)

Authenticates login attempts against the ISS_Users SharePoint list.

  1. Trigger: "When an HTTP request is received" — Method: POST — Body: {"email": "...", "password": "..."}
  2. Action: "Get items" → ISS_Users → Filter Query: Title eq '@{toLower(triggerBody()?['email'])}' and IsActive eq 1
  3. Action: "Condition" — check if length(body('Get_items')?['value']) is greater than 0 AND first(body('Get_items')?['value'])?['Password'] equals @{triggerBody()?['password']}
    • If yes: Response with user data (see below)
    • If no: Response with {"valid": false}

Success response body:

{
  "valid": true,
  "user": {
    "email":        "@{first(body('Get_items')?['value'])?['Title']}",
    "firstName":    "@{first(body('Get_items')?['value'])?['FirstName']}",
    "lastName":     "@{first(body('Get_items')?['value'])?['LastName']}",
    "title":        "@{first(body('Get_items')?['value'])?['JobTitle']}",
    "businessUnit": "@{first(body('Get_items')?['value'])?['BusinessUnit']}",
    "region":       "@{first(body('Get_items')?['value'])?['Region']}",
    "phone":        "@{first(body('Get_items')?['value'])?['Phone']}",
    "manager":      "@{first(body('Get_items')?['value'])?['Manager']}"
  }
}

Configure the App

Once all five flows are created, configure the app with their URLs. This only needs to be done once per device (settings are stored in the browser's localStorage).

Steps
  1. Open login.html and sign in.
  2. On any screen in the app, press Ctrl + Shift + I to open the SharePoint Integration config panel.
  3. Paste the Power Automate HTTP POST URL into each field.
  4. Click Test next to each URL to verify the endpoint is reachable.
  5. Click Save Configuration. The app will immediately sync data from SharePoint.
✅
The status bar at the top of the config panel will turn green and say "SharePoint integration is active" once the required URLs (Get Opportunities + Save Opportunity) are saved.

Managing Users

Once the Validate User flow is configured, user accounts are managed entirely through the ISS_Users SharePoint list.

To add a new user
  1. Go to the ISS_Users SharePoint list
  2. Click + New
  3. Fill in Title (email address, lowercase), Password, first/last name and other fields
  4. Set IsActive to Yes
  5. Click Save — the user can log in immediately
To disable a user

Set the IsActive column to No on their row. They will receive an "invalid credentials" error on next login attempt.

⚠️
Fallback users: The USERS array inside login.html still works as a fallback if the Validate User flow is unreachable (e.g. Power Automate outage). Keep at least one IT admin account in that array.

Troubleshooting & FAQ

The app shows "SharePoint sync failed — saved locally"

The Power Automate flow returned an error or timed out. Check: (1) the URL is correct in the config panel, (2) the flow is turned on in Power Automate, (3) the SharePoint site and list still exist with the correct column names.

Test button shows "Connection failed — check URL & CORS"

Most likely the CORS headers are missing from the flow's Response action. In each flow, open the Response action → Show advanced options → add the three headers listed in Section 4.

Users can't log in even though their SharePoint row is correct

Check that: (1) the IsActive column is set to Yes, (2) the Title column contains their email in all lowercase, (3) the Validate User flow URL is saved in the app's config panel.

Dropdown values in the form don't match SharePoint

The Get Config flow may not be configured, or the ISS_Config list rows use a different Title value than expected. The Title must be exactly: offering, industry, stage, serviceCategory, status, reasonWon, reasonLost (case-sensitive, camelCase).

The app works on my computer but not on others

The Power Automate URLs are stored per-browser in localStorage. Each new device/browser needs the URLs entered once via Ctrl+Shift+I. For a shared deployment, consider embedding the URLs directly in the HTML file's ISS_API object.

Can I host the HTML files on SharePoint itself?

Yes — upload both login.html and iss-opportunity-manager.html to a SharePoint document library and share the link. Authentication will still use the login page. Make sure both files are in the same library folder so relative links work.

How do I embed the Power Automate URLs directly into the HTML file?

Open iss-opportunity-manager.html in a text editor. Find the ISS_API object near the top of the <script> section. Replace the empty strings with your URLs:

let ISS_API = (() => {
  const s = JSON.parse(localStorage.getItem('iss_api_config') || '{}');
  return {
    getOpportunities:  s.getOpportunities  || 'YOUR_URL_HERE',
    saveOpportunity:   s.saveOpportunity   || 'YOUR_URL_HERE',
    deleteOpportunity: s.deleteOpportunity || 'YOUR_URL_HERE',
    getConfig:         s.getConfig         || 'YOUR_URL_HERE',
    validateUser:      s.validateUser      || 'YOUR_URL_HERE',
    ...
  };
})();

This way users never need to configure anything — the URLs are baked in.
